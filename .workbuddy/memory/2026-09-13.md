## LLM 群守卫 · 高召回模式（V1.1.0）开发完成（起于 9-12 深夜）
- 需求：LLM 审核支持高召回模式——每日定时自动开启/关闭，生效期间改用另一套审核要求与单独选择的模型，开启/关闭发送群内提示。
- 新增 `core/high_recall.py`：跨天时段窗口（如 22:00~06:00）、下一个切换节点、时间校验（纯函数，可注入 now）。
- `core/message_guard.py`：`_llm_review_settings()`——高召回生效时替换审核要求 + 主/备/识图模型，留空项沿用常规设置。
- `main.py`：high_recall_* 群配置键；`_check_high_recall()` 挂入调度循环（到点切换 + 提示，失败排队补发）；`web_high_recall_set` 手动切换（override 到下一个定时节点自动交还）；保存配置时校验时间、启用/关闭即时对齐状态；WebAPI 路由已注册。
- `pages/guard/`：新增「高召回」页签（状态 / 定时开关 / 时间 / 模型 ×3 / 审核要求 / 提示语 / 立即开关）。
- `tests/test_high_recall_selftest.py`：13 例自测（窗口数学 / 规则切换 / 调度 / 补发 / WebAPI 注册 / 保存校验与重载），仓库 4 个自测全绿。
- 设计结论：违规处置方式**不随**高召回变化，仍按群的 guard_action（ban/recall/recall_and_ban，默认禁言）。
