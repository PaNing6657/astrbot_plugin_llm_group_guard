## 群名片锁定功能（参考 astrbot_plugin_gcard_keeper 实现）

**需求**：锁定单个用户的群名片，并在插件自带 WebUI 中支持前端操作。

**实现要点**
- 新增 `core/card_lock.py`（387 行，不 import astrbot，可离线单测）：
  - `normalize_lock_rules` / `validate_lock_rule` / `find_lock_rule` / `is_card_locked` 纯函数
  - `CardLockEngine`：依赖全部构造注入（gconf_provider / is_managed / client_provider / notifier / warn_unmanaged / groups_provider）
- 事件驱动：**aiocqhttp 原生 `bot.on_notice()`** 捕获 `group_card`。
  关键认知：AstrBot 消息管线会把 notice 转成空消息（message_str=""）并在唤醒检查阶段丢弃，
  所以 `@filter.event_message_type` **收不到**群名片变更，必须挂原生回调。
- **回声抑制**：机器人自己 `set_group_card` 也会触发 group_card 通知，
  用 `mark_self_write` / `consume_self_write` + 10s TTL 窗口避免在新旧名片间反复横跳。
- 轮询兜底挂既有 `_schedule_loop`（`_check_card_locks`），按群独立节流，最小 60s。
- 新增 5 个 WebAPI：`card-lock/{list,set,delete,apply,sync}`；非管理群后端也门控（前端禁用不可信）。

**踩坑**
1. `card_lock_list` 是 dict 列表，**不能**放进 `_LIST_CONFIG_KEYS`（`_normalize_list_value` 会把它压成字符串），
   必须在 `_normalize_group_lists` 里单独用 `normalize_lock_rules` 处理。
2. 该仓库存在**外部自动提交进程**：改完文件 git status 显示"未修改 + 新文件不出现"，
   实际已被自动 commit。核对方式：`git log --oneline` + `git show --stat <sha>`。改完要用 grep 复核落盘。
3. 自测桩 `_register(*args)` 必须支持关键字参数（`@filter.llm_tool(name=...)`），
   否则报 `unexpected keyword argument 'name'`。
4. main.py 用相对导入，自测里必须 `importlib.import_module(f"{pkg_name}.main")` 包方式导入。
5. 测试脚本里 `make_engine(rules=..., bot=bot2)` 若 `bot2` 在同一函数内先赋值后使用没问题，
   但写成 `engine, bot2, ... = make_engine(..., bot=bot2)` 会触发 `UnboundLocalError`（同名赋值被视为局部变量）。
